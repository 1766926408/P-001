## 技术架构概览

### 系统分层

```
客户端层：Gradio (MVP) / React (正式) / VSCode 插件 / 微信企微
    ↓
API 网关层：Nginx / Traefik（SSL 终结、限流、负载均衡）
    ↓
应用服务层：FastAPI (async) + LangGraph Agent + Celery 后台任务
    ↓
核心引擎层：RAG 引擎 / LLM 适配器 / 代码分析器 / 语义缓存
    ↓
数据存储层：PostgreSQL / Qdrant / Redis / MinIO
    ↓
外部服务层：DeepSeek(主) / GLM-4(备) / Ollama(离线降级)
```

### 技术栈

- **后端框架**：FastAPI + FastAPI-CORS
- **向量数据库**：Qdrant（生产级，替代 ChromaDB）
- **缓存**：Redis L1 + PostgreSQL L2 双级语义缓存
- **文件存储**：MinIO（生产化文件持久化）
- **任务队列**：Celery + Redis broker
- **前端**：React（11 页面完整设计）+ Gradio（保留备用）
- **容器化**：Docker + Docker Compose + Nginx

## P0 核心功能

| 功能 | 说明 |
|-----|------|
| **RAG 知识问答** | TI/ST/Microchip 手册 + 算法文档，支持跨语言检索 |
| **代码审查（三级）** | 单文件 / 多文件跨调用 / 全工程，AST 符号追踪 |
| **PID 智能调参** | 结构化参数表输出 + 历史记录追踪 |
| **跨平台代码移植** | STM32/C2000/Microchip/FPGA/DSP，自动标注平台差异 |
| **算法调试验证** | FOC/SVPWM/无感算法正确性验证 |
| **单位量纲安全检查** | rpm/rad/s、峰值/有效值、电角度/机械角度等 |
| **故障根因诊断** | 诊断优先：列原因→判断方法→确认后给方案 |

## 关键决策

- **知识库**：130 份文档，6535 个知识块，Qdrant 向量存储
- **代码审查**：50 条规则（MC001~MC050），3 级深度（文件/跨文件/全工程）
- **故障案例**：90 条（FC001~FC090），16 个分类
- **代码模板**：覆盖 STM32/C2000/ESP32/dsPIC/Arduino/GD32
- **性能基准**：PID 计算 <10ms，通信吞吐达标，长时间稳定性 ≥8h
