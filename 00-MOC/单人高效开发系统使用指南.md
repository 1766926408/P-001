# 单人高效开发系统使用指南

> **为 MM 项目（P-001）量身定制的私密、高效的开发管理系统**

---

## 📋 系统组成

### **三层管理体系**

```
外部源文件（权威、不动）
├── 开发计划.md
├── 电机控制AI助手-完整详细设计.md
└── 电机控制AI助手-产品方案.md
        ↓
Obsidian 同步镜像（隐晦化）
├── P-001 项目地图与开发追踪
├── P-001 完整详细设计
└── P-001 完整产品方案
        ↓
自动化工具（进度清单 + Bug 统计）
```

### **核心规则**

- ✅ **源文件不动**：外部文件保持原样，我维护同步
- ✅ **本地隐私**：Obsidian 只在本地，不云端
- ✅ **完全隐晦**：项目名 = P-001，应用场景 = Scenario-A
- ✅ **高度自动**：进度更新、Bug 统计、周报生成全自动

## 🎯 日常工作流

### **每日**（5 分钟）

```
早上 9:00 
  ↓
[可选] 告诉我："生成今日进度清单"
  ↓
获得：
  - 本周重点是什么
  - 下一个任务是什么
  - 有没有风险/阻碍
  ↓
开始编码
```

### **每周五 EOD**（10 分钟）

```
下班前
  ↓
告诉我：
"本周完成了：
  - 7.7 框架搭建（进度 30%）
  - 修复 BUG-001
  - 遇到问题：xxx，下周计划 xxx"
  ↓
我自动：
  1. 更新外部源文件（开发计划.md）
  2. 同步 Obsidian 镜像
  3. 生成周报（代码提交、功能完成、问题汇总）
  4. 更新 Bug 统计
  ↓
你下周直接看周报继续开发
```

### **每月底**（可选）

```
告诉我："生成本月月报"
  ↓
获得：
  - 本月完成度
  - Bug 修复统计
  - 质量趋势
  - 改进建议
  ↓
评估进展，调整下月计划
```

## 🛠️ 自动化工具使用

### **进度清单生成**（支持所有项目）

**触发方式**：
```
默认（所有公司项目）：
  "生成今日进度清单"
  "生成本周进度清单"

指定项目：
  "生成 P-001 的进度清单"
  "生成 MM 的今日进度清单"
  "生成[公司项目名]的进度清单"
```

**获得内容**：
- 本周重点任务
- 下一个待处理任务
- 当前的风险/阻碍
- 本周/本月完成总结

**推荐频率**：
- 每天早上 9:00（帮助规划一天）
- 每周五 17:00（周报）

---

### **Bug 统计分析**（支持所有项目）

**触发方式**：
```
默认（所有公司项目）：
  "生成 Bug 统计"
  "生成本周 Bug 报告"

指定项目：
  "生成 P-001 的 Bug 统计"
  "分析 MM 的 Bug 趋势"
  "生成[公司项目名]的 Bug 统计"
  "列出 P-001 的未解决 Bug"
```

**获得内容**：
- Bug 总数、已解决、未解决
- 按项目、按类型的分布
- 平均解决周期
- 质量趋势、改进建议

**推荐频率**：
- 每周五（周报中包含）
- 每月底（质量评估）

## 📝 如何更新进度

### **告诉我进度时的标准格式**

```
"本周完成了：
  - 7.7 自动化测试框架搭建（进度 30%）
    细节：pytest 已集成，GitHub Actions 配置中，工具函数库待完善
  - 7.8 单元测试用例（进度 10%）
    细节：开始写 PID 模块的测试
  - 修复 BUG-006（已解决）
  - 遇到问题：性能基准采集困难
    计划：下周研究 xxxx"
```

**我会自动**：
1. 更新 `开发计划.md` 中的条目状态和进度
2. 同步 Obsidian MOC 镜像
3. 如有新 bug，在 `03-Bugs/` 中记录
4. 生成周报

### **命名规范**

| 内容 | 代码 | 说明 |
