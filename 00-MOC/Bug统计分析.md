# Bug 统计与分析工具

> **用途**：自动分析 Bug 记录，提供质量趋势、修复周期、风险预警等数据。

---

## 使用方式

### 项目识别
- **默认**：`"生成 Bug 统计"` → 所有公司项目
- **私人项目**：`"生成 P-001 的 Bug 统计"` → 仅 P-001
- **公司项目**：`"生成[项目名]的 Bug 统计"` → 指定项目

详见 [[项目识别规则]]

### 按需查询
```
告诉我："生成 Bug 统计"
或
告诉我："生成 P-001 的 Bug 统计"（如果指定项目）
或
告诉我："分析 MM 的 Bug 趋势"（MotorMind = P-001）
```

我会自动分析：
- 📊 Bug 总数、未解决数、解决数
- 📈 按项目、按类型、按时间的分布
- ⏱️ 平均解决时间
- ⚠️ 高风险未解决条目

### 定期报告（推荐）
```
我配置 /schedule 定时任务：
  - 每周五生成周报（Bug 新增、修复情况）
  - 每月底生成月报（质量趋势、改进建议）
```

## 统计维度

### 按时间
- 今日、本周、本月、累计
- 解决周期（从创建到解决的天数）

### 按项目
- P-001 的 Bug 统计
- P-002 的 Bug 统计
- 按项目的平均解决时间

### 按类型
- I2C / 硬件通信
- 控制算法
- 软件框架
- RTOS / 并发
- 其他

### 按严重等级
- Critical（阻塞开发）
- High（影响功能）
- Medium（性能问题）
- Low（文档/工具）

## 数据来源

| 数据 | 来源 |
|-----|------|
| Bug 列表 | `03-Bugs/Bug记录索引.md` + 各 BUG-XXX.md |
| 项目分类 | 各 Bug 记录的 `项目:` 字段 |
| 标签分类 | 各 Bug 记录的 `tags:` 字段 |
| 解决时间 | Bug 记录的 `记录日期:` 和 `状态:` |
