# 项目识别规则

> **两个自动化工具（进度清单 + Bug 统计）适用于所有项目，自动识别项目范围。**

---

## 识别原则

### **规则 1：默认是公司项目**
```
"生成进度清单" 
→ 默认扫描所有公司项目

"生成 Bug 统计"
→ 默认扫描所有公司 Bug 记录
```

### **规则 2：明确提及时是指定项目**
```
"生成 P-001 的进度清单"
→ 仅扫描 P-001 项目

"生成 MotorMind 的 Bug 统计"
→ 仅扫描 P-001 相关 Bug 记录
```

## 识别示例

### ✅ 默认公司项目

```
用户："生成进度清单"
我：扫描所有公司项目的开发计划
  → 汇总各项目进度
  
用户："生成 Bug 统计"
我：扫描所有公司 Bug 记录
  → 统计所有 Bug 的质量数据
```

### ✅ 指定私人项目

```
用户："生成 P-001 的进度清单"
我：仅扫描 P-001 的开发计划
  → 展示 P-001 的进度

用户："生成 MM 的 Bug 统计"
我：自动识别 P-001，仅统计相关 Bug
  
用户："生成 MotorMind 的进度清单"
我：自动识别 P-001
```

### ✅ 指定公司项目

```
用户："生成[公司项目名]的进度清单"
我：仅扫描该项目的进度

用户："生成灌溉系统的 Bug 统计"
我：仅统计该项目相关 Bug
```

---

## 自动识别流程

```
用户输入
  ↓
检测是否提及项目名称
  ├─ 是 P-001/MM/MotorMind → 识别为 P-001
  ├─ 是 P-002/IMU → 识别为 P-002
  ├─ 是公司项目名 → 识别为该项目
  └─ 都没有 → 默认公司所有项目
  ↓
调用对应的工具
  ├─ 进度清单：扫描对应项目的开发计划
  └─ Bug 统计：扫描对应项目的 Bug 记录
  ↓
生成结果
```

## 特殊情况处理

### 情况 1：有歧义怎么办？
```
用户："生成 IMU 的进度清单"
我：询问确认
  "IMU 是指 P-002（IMU工具）吗？还是公司的 IMU 项目？"
```

### 情况 2：公司项目名与代码冲突？
```
如果公司项目名是"P-001"或"P-002"：
→ 优先识别为私人项目代码
→ 如需指定公司项目，用完整名称
```

### 情况 3：只提项目名，不提工具名怎么办？
```
用户："P-001 怎么样了？"
我：询问确认
  "你是要生成 P-001 的进度清单还是 Bug 统计？"
```
