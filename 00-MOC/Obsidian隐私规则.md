# Obsidian 隐私规则

> **原则**：降低辨识度，保护私人项目隐私。不体现应用场景、项目名称。

---

## 隐私分级

### 🔴 **禁止记录**（完全不涉及）
- 客户名称、联系信息
- 具体应用场景（如"无人机"、"机器人"、"灌溉系统"）
- 商业数据（定价、用户数、收入）
- 上线时间、推出计划

### 🟡 **隐晦化记录**（代码化表示）
- **项目名称** → 用内部代码（如 P-001）
- **功能描述** → 仅保留技术名词（器件、算法、协议）
- **应用背景** → 用通用术语（"控制系统"、"嵌入式应用"等）

### 🟢 **允许详细记录**（技术层面）
- 系统架构、技术栈
- 算法实现、优化方案
- Bug 原因分析、解决方案
- 性能指标、质量数据
- 代码审查、最佳实践

## 具体示例

### ❌ 不好的记录

```markdown
# BUG-007 BNO080 在无人机应用中磁力计 acc 为 0

现象：
在无人机的姿态控制模块中，BNO080 传感器的磁力计加速度输出始终为 0...

项目：无人机控制系统
```

### ✅ 好的记录

```markdown
# BUG-007 BNO080 磁力计 acc 为 0

现象：
传感器磁力计加速度输出始终为 0，影响闭环控制...

项目：P-001
```

---

### ❌ 不好的项目文档

```markdown
# MotorMind 完整产品方案

**产品定位**："电机控制领域的专家 AI 助手"
**目标用户**：工业驱动、无人机、新能源汽车、机器人等
**应用场景**：FOC 调试、参数辨识、硬件审查...

# P-001 完整产品方案

**产品定位**：专业控制领域的智能助手
**目标用户**：控制工程师、嵌入式开发者
**应用领域**：嵌入式控制系统、实时处理...
```

## 命名规范

### 项目代码
- **P-001**、**P-002** 等（私人项目）
- **OP-001** 等（开源项目，如有）

### 场景代码
- **Scenario-A**、**Scenario-B** 等（通用，不涉及具体应用）
- 或直接用技术术语：**实时控制系统**、**嵌入式应用**等

### 需求代码
- **REQ-001** ~ **REQ-XXX**（具体需求）
- 仅在技术讨论时使用，不暴露业务背景

## 审查清单

发布/提交前检查：

- [ ] 项目名称已代码化？（MotorMind → P-001）
- [ ] 应用场景已移除或通用化？（"无人机" → "嵌入式应用"）
- [ ] 客户/用户信息已移除？
- [ ] 商业数据已移除？（定价、用户数等）
- [ ] 技术细节保留完整？（算法、架构、性能指标）
- [ ] 降低辨识度？（陌生人看不出具体项目）
